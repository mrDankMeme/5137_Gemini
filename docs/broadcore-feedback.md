# Отзыв по BroadApps iOS Platform (ветка `vers_niiaz`)

Написано после реальной сборки нового приложения **5137 Gemini** с нуля на платформе:
от `git clone` до `BUILD SUCCEEDED` с подключёнными `BroadCore`, `BroadMonetization`,
`BroadUIFlows`, `BroadExtensions`. Всё ниже — то, обо что споткнулся на практике,
а не вычитал.

## Что сразу хорошо

- Разделение на четыре модуля читается без объяснений: понятно, что где искать.
- Продуктовые правила в `AGENTS.md` — сильная часть. Пункты про «offline не превращается
  в success», «purchase не открывает premium до подтверждения entitlement» и
  «`isInFlight = true` до `Task`» закрывают ровно те баги, которые обычно ловит тестировщик.
- Таблица «когда пользователь увидит RU Billing» с явным «ИЛИ» — то, что раньше
  приходилось выяснять чтением чужого кода.
- Требование держать все временные значения в одном файле и перечислять их в отчёте.

## Блокеры

### 1. Приватный пакет не ставится по адресу из README

README даёт ровно это:

```text
https://github.com/BroadApps-official/BroadCore.git
branch: vers_niiaz
```

Подставляем в SPM — и сборка падает ещё до компиляции:

```
Failed to clone repository https://github.com/BroadApps-official/BroadCore.git:
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

Репозиторий приватный, а Xcode не умеет спросить логин. Слов `SSH`, `git@`, `insteadOf`,
`personal access token` в README и `GettingStarted.md` **нет ни одного**. То есть первый же
шаг инструкции не работает, и каждый разработчик чинит это сам.

Локально помогло:

```bash
git config --global url."git@github.com:BroadApps-official/".insteadOf \
  "https://github.com/BroadApps-official/"
```

**Просьба:** добавить в README отдельный шаг «доступ к пакету» — SSH-адрес либо эту команду,
и **что именно настроить в Codemagic**, чтобы CI тоже смог достать приватный пакет.
Сейчас про CI не сказано ничего, и это выяснится в момент первой сборки релиза.

### 2. `BroadAppTemplate` нельзя взять за основу — он не самодостаточен

README говорит: «Используй BroadAppTemplate как пример соединения модулей».
Открываем `AppCompositionRoot.swift` — 308 строк, и он держится на типах
`ExampleMonetizationEnvironment`, `ExampleCacheDependencies`, `ExampleBootstrapScenario`,
`ExampleEntitlementDependencies`, `ExampleLiveAdaptyServicesFactory` и других.

Проверил: **ни одного из них нет в `Sources/`** — они живут только внутри примера.
Значит скопировать composition root в новое приложение нельзя: надо переписать
примерно десяток вспомогательных типов, догадываясь, какие куски были демонстрацией,
а какие обязательны.

**Просьба, в порядке полезности:**

1. Дать в документации **минимальный** composition root — самый короткий рабочий код,
   который поднимает `BroadCoreAssembly → BroadMonetizationAssembly → BroadUIFlowsAssembly`
   для обычного приложения с подпиской. Строк на 40, не на 308.
2. Перенести разумные умолчания из примера в пакет
   (условный `BroadDefaultMonetizationEnvironment`), чтобы хост-приложение
   переопределяло только то, что у него правда своё.
3. В самом примере пометить комментарием, что `Example*` — демонстрация, а не образец
   для копирования.

### 3. `AGENTS.md` написан для другого читателя

README (шаг 1 варианта A) прямо велит: «Claude нужно попросить прочитать `AGENTS.md`».
Читаю — и первые же строки: «Работай только внутри `BroadAppsIOSPlatform`»,
«не создавай `Tests`», «запусти `bash Scripts/agent_gate.sh`», «не изменяй
reference-проекты `5013`, `5109Codex`, `Claude232` и `Шаблон`».

Для агента, который делает **новое приложение в отдельной папке**, половина файла —
не его правила, а правила контрибьютора платформы. При этом вторая половина
(«Обязательные продуктовые правила») — как раз то, что ему обязательно нужно.

**Просьба:** разделить на два файла — правила для тех, кто меняет саму платформу,
и правила для хост-приложения. Второй должен быть коротким и состоять только из
продуктовых требований: ATT, Rate Us, порядок продуктов, entitlement, offline,
`isInFlight`, Keychain, Usedesk, письмо в поддержку.

## Чего не хватает в README

### 4. Нет короткого маршрута

README — 2310 строк. Чтобы дойти до первой строчки кода, надо прочитать про два
варианта работы, Kaiten, правила Adapty, RU Billing и готовый промпт.
`Documentation/GettingStarted.md` (700 строк) есть, но ссылки на него в начале нет.

**Просьба:** в самом верху блок «нужно только это»: доступ к пакету → подключить 4 продукта →
минимальный composition root → маршрут `splash → onboarding → paywall → проверка → main`.
Остальное — по ссылкам.

### 5. Про Figma сказано «открой», но у разработчика нет edit-доступа

README строит выбор на метке `no-code`: есть — Claude Design, нет — Figma.
На практике проект с Figma упирается в другое: **Figma MCP требует edit-доступа к файлу**,
а дизайнер выдаёт просмотр. Все read-инструменты MCP отвечают
«Looks like you don't have edit access to this file» — и это не квота, это права.

Рабочий обход — **Figma REST API** с личным токеном: ему хватает просмотра, он не тратит
лимит MCP и отдаёт документ целиком (`GET /v1/files/{key}`) плюс рендер любого узла
(`GET /v1/images/{key}?ids=…&scale=3`). На 5137 так снялись все 14 страниц, 85 экранов
и вся дизайн-система. Через MCP было видно только 3 страницы из 14.

**Просьба:** описать этот путь в README как штатный, а не оставлять каждому находить его заново.

### 6. Нет шаблона временной конфигурации

README честно говорит: пока данных нет — бери development-конфигурацию похожего
live-приложения и держи в одном файле. Но самого файла-шаблона в платформе нет.

На 5137 в Kaiten заполнены **только** Figma и Git: ни bundle, ни Adapty-ключа, ни продуктов,
ни ссылок PP/ToU. Это, судя по всему, обычное состояние в начале работы.

**Просьба:** положить в платформу `DevelopmentConfiguration`-шаблон со всеми полями,
которые понадобятся (bundle, Adapty key, placements, продукты, ссылки, support), и
пометкой `// ВРЕМЕННОЕ — заменить перед релизом` у каждого. Тогда список «что заменить»
собирается сам, а не пишется руками в отчёте.

## Мелочи

- **Версии зависимостей прибиты жёстко:** `Adapty exact 3.17.3`, `Swinject exact 2.10.0`.
  Если это осознанно — стоит написать почему, иначе хост-приложение с другой версией
  Adapty не соберётся, и будет непонятно, можно ли двигать.
- **Тулчейн.** Бейдж говорит «Xcode 16+», а Codemagic собирает `xcode: latest`.
  Полезно указать, на каких версиях платформа реально проверялась. Данные с моей стороны:
  на **Xcode 27.0 (Swift 6.4)** пакет и приложение собираются без ошибок и предупреждений.
- **`AgentChecks/STATUS.md`** упоминается в порядке исправления, но для хост-приложения
  непонятно, надо ли его читать. Стоит явно написать «только для контрибьюторов платформы».
